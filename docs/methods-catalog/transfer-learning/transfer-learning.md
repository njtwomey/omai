# Transfer learning (part 5, learning paradigms)

Learning that reuses what was learned elsewhere: fine-tuning and feature transfer from a pretrained network (which layers to keep, how much target data it takes), domain adaptation between a source and a target with a planted shift (importance weighting, CORAL, MMD and adversarial alignment, self-training, optimal transport), label-shift estimation, domain generalisation (invariance penalties, group robustness), continual learning (forgetting and what prevents it) and federated averaging across clients, as sessions over `nn`, `optim`, `learn`, `autodiff`, `kernels` and the shift modifiers of `data`. Meta-learning (learning to learn across tasks) and multi-task learning (learning several tasks at once) are their own chapters.

## Structure

Every method here trains a network or reweights a fit under a changed distribution, so it lives under `train/transfer/` (section 3 of `methods/README.md`), one folder per setting; federated learning is a folder rather than its own area because it shares the trainer, the client partitions and the drift measures with the rest. The shift studies that only measure (how much a model degrades under a shift, no adaptation) are `data/shift/` and the `shift-and-drift` chapter's.

```
train/transfer/
  fine-tuning/          linear probe, full and partial fine-tuning, adapters, layer transferability, accuracy against target size
  domain-adaptation/    importance weighting, CORAL, MMD alignment, DANN, self-training, optimal-transport alignment
  label-shift/          black-box shift estimation, EM prior adjustment, posterior reweighting
  domain-generalisation/  invariant risk minimisation, group DRO, leave-one-domain-out
  continual/            sequential fine-tuning (forgetting), elastic weight consolidation, experience replay, the accuracy matrix
  federated/            FedAvg, FedProx, SCAFFOLD, server optimisers, personalisation, differentially private rounds
  shared/               pretrained sources, the source-target slot, gradient reversal, alignment losses, client partitions, forgetting metrics (below)
```

## Methods

Tags on tracks: `s` a per-step scalar, `t` a per-step tensor at summary detail, `t!` a tensor kept in full, `p` a probe computed from the state at any step, `proj` a projection over the tape, `e` an event, `m` a message with a payload. The trainer base logs `training/loss`, `training/gradNorm`, `eval/<metric>` at its schedule and `model/params` for every method here; the rows list what each adds. Every comparison runs on the same keys, so the source model, the shift and the start are identical across the variants.

| `self-training` | Pseudo-labels on the target above a confidence threshold (knob) added to the training set each round: the labelled target set growing, the accuracy of the pseudo-labels (the truth is known), the confirmation bias when the threshold is low.
