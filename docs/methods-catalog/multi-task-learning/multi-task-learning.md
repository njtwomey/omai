# Multi-task learning (part 5, learning paradigms)

Several tasks learned at once by one model, and the question of when that helps: hard and soft parameter sharing (a shared trunk with task heads, coupled networks, cross-stitch units, task-routed experts), task weighting (uncertainty weighting, GradNorm, dynamic weight averaging), gradient conflict and its surgery (PCGrad, CAGrad, the multiple-gradient descent algorithm and the Pareto front of tasks), auxiliary tasks, negative transfer with planted task relatedness, and the task-affinity question (which tasks to train together), as sessions over `nn`, `autodiff` (per-task gradients), `optim` and `losses`. Transfer learning (one task after another) and meta-learning (learning to adapt across tasks) are their own chapters; multi-output regression in the task-method world is `fit/regress/` and cross-referenced here.

## Structure

Every method here trains one network on several losses, so it lives under `train/multitask/` (section 3 of `methods/README.md`), one folder per question.

```
train/multitask/
  parameter-sharing/    hard sharing (trunk and heads), soft sharing (coupled parameters), cross-stitch, task-routed experts
  task-weighting/       uniform, uncertainty weighting, GradNorm, dynamic weight averaging, random weighting, as one method with the rule as a mode
  gradient-methods/     per-task gradients and their conflict, PCGrad, CAGrad, MGDA, the Pareto front of task losses
  auxiliary-tasks/      a main task with auxiliaries, their weight and gating
  task-relationships/   negative transfer against planted relatedness, task affinity and grouping, multi-output regression (cross-reference)
  shared/               multi-task data with planted relatedness, trunk-and-heads factories, weighting rules, per-task gradients, records (below)
```

## Methods

Tags on tracks: `s` a per-step scalar, `t` a per-step tensor at summary detail, `t!` a tensor kept in full, `p` a probe computed from the state at any step, `proj` a projection over the tape, `e` an event, `m` a message with a payload. Every method here logs the per-task losses and metrics as tensors indexed by task (`task/loss`, `eval/taskMetric`), so one small-multiples panel serves the whole chapter, and runs the single-task baselines under the same budget and keys as the comparison.

## Problems

- New chapter: the old `transfer-and-meta-learning` folded multi-task learning into one bullet; it was split out on 2026-10-28.
- Per-task gradients cost one backward pass per task per step; at toy scale that is fine, and the worker producer (`methods/README.md` section 6, problem 7) is what makes it fine at any other.
- The weighting rules and the gradient surgery are a few lines each and start in `shared/`; they belong in `optim` as gradient transformations over a list of per-task gradients once a second chapter (`reinforcement-learning`'s multi-objective agents) wants them.
