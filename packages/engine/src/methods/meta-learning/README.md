# Meta-learning (part 5, learning paradigms)

Learning to learn: a distribution of tasks rather than one dataset, and a learner judged by how fast it adapts to a new task from a few examples. Optimisation-based methods (MAML and its first-order, head-only and implicit variants, Reptile), metric-based methods (prototypical, matching and relation networks, siamese embeddings), model-based methods (memory and in-context learners, neural processes), hypernetworks, learned optimisers and hypergradients, and meta-learning for hyperparameters, as sessions over `nn`, `autodiff` (second-order and implicit differentiation), `optim` and `tune`. Transfer learning (one source, one target) and multi-task learning (several tasks at once) are their own chapters.

## Structure

Every method here trains across episodes drawn from a task distribution, so it lives under `train/meta/` (section 3 of `methods/README.md`), one folder per family; the hyperparameter rows are studies and point at `study/`.

```
train/meta/
  optimisation-based/   MAML, first-order MAML, ANIL, Reptile, implicit MAML; the few-shot fit after k steps as a probe
  metric-based/         prototypical networks, matching networks, relation networks, siamese and triplet embeddings
  model-based/          memory-augmented learners, in-context learning by a transformer, neural processes
  hypernetworks/        a network generating another's weights from a task embedding
  learned-optimisers/   an optimiser that is a recurrent network, hypergradient descent on the learning rate
  hyperparameters/      bilevel hypergradients (unrolled and implicit), warm-started tuning across tasks
  shared/               task distributions, episodes, the inner loop, adaptation records (below)
```

## Methods

Tags on tracks: `s` a per-step scalar, `t` a per-step tensor at summary detail, `t!` a tensor kept in full, `p` a probe computed from the state at any step, `proj` a projection over the tape, `e` an event, `m` a message with a payload. The step of a meta-learner is one outer (meta) update over a batch of tasks; the inner loop of a task is a sub-session whose curve is a probe at any outer step, so a page can show "adapt to this new task from the meta-parameters at step 400" without re-running the meta-training.

## Examples to make

- MAML on sinusoids: after meta-training, one task fitted in five gradient steps, drawn step by step, beside the pooled-pretraining baseline that can only draw the mean sinusoid.
- Prototypical networks on 5-way 1-shot digit episodes: the embedding with prototypes and queries at the viewed step, the shot curve.
- In-context linear regression: a transformer's error against context length converging on ridge regression's.
- Hypergradients for the ridge penalty: unrolled against implicit, the penalty's trajectory and the validation loss, against the grid.

## Problems

- The inner loop is a session inside a session: the adaptation sub-session needs the outer state at a step, which the checkpoints give, but its own tape should not be kept for every outer step (the `keep` option of 7.7 covers it, with the curve as a tensor per outer step).
- Second-order MAML needs `grad` of a function that itself calls `grad`; `autodiff` supports nesting (`hessian`, `hvp`), but the cost at network scale waits on the worker producer like everything in `train/`.
- The task distributions start in `shared/tasks.ts`; the few-shot image episodes want more classes than the vendored sets offer (Omniglot is the standard, with a permissive licence: `methods/README.md` 7.11).
